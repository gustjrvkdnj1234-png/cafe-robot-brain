## 6b 해석

**1. 점수는 사실상 그대로다.**

- 30문항 정답 수는 64개 CPU만 28 → 29이고 나머지는 같다. 바뀐 문항은 T1-1(포장) 하나로, 6a에서는 손님이 확정하지 않았는데 `confirm_order`까지 불렀고 6b에서는 부르지 않아 맞혔다. 포장 유형은 3·5단계에서도 모델·실행마다 흔들리던 문항이다.
- 나머지 ‘도구 호출이 달라진 문항’은 모두 안내 문장의 표현만 다르다(`normalize_call`로 정리하면 같음). 점수는 메뉴·옵션·이유만 보므로 영향이 없다.

**2. 메모리는 모델마다 약 3.3 GB 줄었고, 16 GB 노트북에 CPU로는 들어간다.**

- 정상 상태 메모리(중앙값): 64개 CPU 13.4 → 10.1 GB, 48개 CPU 11.7 → 8.4 GB. iGPU는 64개 15.0 → 11.8 GB, 48개 13.3 → 10.1 GB.
- 16 GB 노트북(OS 4 GB + 모델 최댓값): 64개 CPU는 14.9 GB로 **아슬아슬(여유 1.1 GB)**, 48개 CPU는 13.2 GB로 **들어간다(여유 2.8 GB)**. 64개 CPU를 쓰려면 브라우저 등 다른 프로그램을 거의 띄우지 않아야 한다.
- iGPU는 RAM 총량으로는 48개가 들어가지만(14.3 GB), GPU 공유 메모리가 64개 11.9 GB, 48개 10.2 GB라서 Windows가 보통 주는 한도(RAM의 절반, 약 8 GB)를 넘는다. 16 GB 노트북에서는 CPU로 돌리는 것이 현실적이다(16 GB 기계로 직접 확인한 것은 아님).

**3. 부분별로 줄인 양 (로딩 로그 기준, 64개·48개 같음)**

- 비전 프로젝터: 약 1.26 GB. 가장 크고, 카페 로봇에는 대가 없이 뺄 수 있다.
- 초안(MTP) 모델: CPU 0.77 GB, iGPU 1.10 GB. 대신 생성 속도가 떨어진다(아래 4).
- 보통 SWA 캐시: 본 모델 KV는 1.72 → 0.55 GB로 1.17 GB 줄지만, 앞부분 재사용을 위한 체크포인트(최대 4개 × 200 MiB = 0.78 GB)가 생겨 실제로 줄어든 것은 약 0.39 GB다.
- 로그 합계(2.4~2.8 GB)보다 실제 측정 차이(3.2~3.3 GB)가 0.5~0.9 GB 더 크다. 초안 모델·프로젝터가 실행 중에 추가로 잡는 메모리로 보이지만, 로그에 나오지 않아 확인하지는 못했다.

**4. 대가: 느려졌다. 특히 주문 내역이 바뀌는 경우.**

- 생성 속도(초안 모델 제거): CPU 14.5 → 12.5 tok/s, iGPU 20.4 → 13.6 tok/s(64개). 초안 모델이 토큰 3개를 미리 맞혀 주던 이득이 사라졌다.
- 앞부분을 다시 쓰는 경우의 첫 토큰(체크포인트 복사): CPU 0.70 → 0.89 s로 조금, iGPU 0.71 → 3.62 s로 많이 느려졌다. 처리하는 토큰은 20여 개뿐인데 200 MiB짜리 SWA 체크포인트를 만들고 되살리는 데 시간이 든다(iGPU는 GPU↔메모리 복사가 느린 것으로 보임).
- 주문 내역이 바뀌는 경우: CPU 26 → 71 s, iGPU 5.8 → 15.7 s. 갈라지는 지점(2,362 토큰) 앞에 체크포인트가 없어서 llama-server가 프롬프트 전체(약 3,500 토큰)를 처음부터 다시 계산했다(로그의 ‘forcing full prompt re-processing’ 16번 = 4문항 × 4번 실행).
- 주문 1건 중앙값: 64개 CPU 3.16 → 3.80 s, iGPU 2.55 → 6.46 s.

**5. 정리와 제안 (아직 하지 않음)**

- 16 GB 노트북 + 64개라면 ‘텍스트 전용 + CPU’가 유일하게 들어가는 조합이다. 다만 주문 내역이 바뀔 때마다 70초가 걸리므로 실제 로봇으로는 쓸 수 없다.
- 가장 큰 문제는 메모리가 아니라 **프롬프트 배치**다. 주문 내역을 도구 설명 뒤로 옮겨 바뀌는 부분이 프롬프트 맨 끝에만 오게 하면, 이 70초가 사라질 가능성이 크다. 다만 보통 SWA 캐시에서는 체크포인트가 갈라지는 지점 바로 앞에 있어야 하므로, 실제로 되는지는 재 봐야 한다. 프롬프트가 바뀌므로 카페·실전 점수도 다시 재야 한다.
- 중간안: SWA 전체 길이는 유지하고 프로젝터·초안 모델만 빼면, 64개 CPU는 약 13.4 − 1.26 − 0.77 ≈ 11.4 GB(16 GB 노트북 기준 15.4 GB, 여유 약 0.6 GB)로 어림된다. 앞부분 재사용은 6a처럼 빠르지만 생성 속도는 6b처럼 느리다. 이 조합은 재지 않았다.
