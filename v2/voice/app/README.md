# 음성 주문 데모 (2단계)

노트북 하나에서 인터넷 없이 돌아가는 음성 주문 앱이다. 한 턴은 이렇게 처리된다:

1. **STT**: faster-whisper medium int8(CPU, 한국어 고정)이 말을 글로 바꾼다.
2. **두뇌**: `song/gemma4-26b-cafe-64e`(v1 64e 전체 빌드)가 도구를 고른다. 기본은 **CPU 전용**이다.
3. **답**: 짧은 템플릿(`replies.json`)으로 만든다. 메뉴 안내는 `menu.json`에서 바로 만든다.
4. **TTS**: Supertonic 3 int8(기본 여성 sid 0, 4단계)이 읽는다. Windows Heami로 바꿀 수 있다.

## 실행과 종료

```
powershell -ExecutionPolicy Bypass -File v2\voice\app\start_demo.ps1 -Open
powershell -ExecutionPolicy Bypass -File v2\scripts\stop_ollama.ps1        # Ollama만 따로 끌 때
```

- **Ollama 시작:** `start_ollama.ps1`로 띄운다. 서버 프로세스에만 `OLLAMA_IGPU_ENABLE=1`, `LLAMA_ARG_CACHE_RAM=0`, `OLLAMA_NOPRUNE=1`을 주고, 로그로 NOPRUNE를 확인한다. 이미 떠 있는 서버를 쓰려면 `-UseRunning`을 붙인다.
- **준비:** 약 40초(엔진 10초, 64e 예열 30초) 뒤 `http://127.0.0.1:8770/`이 뜬다.
- **종료:** Ctrl+C나 앱 종료 시 이 스크립트가 띄운 Ollama를 `stop_ollama.ps1`로 끄고, 프로세스와 포트가 닫혔는지 확인한다.
- **서버 옵션:** `-AppArgs`로 넘긴다. 예: `-AppArgs "--mode igpu --config v1 --history text --layout deploy --max-turns 0"`.

| 옵션 | 기본 | 뜻 |
|---|---|---|
| `--config` | `demo` | 데모 프롬프트와 도구(아래). `v1`은 실험 프롬프트·도구 그대로 |
| `--mode` | `cpu` | CPU 전용(`num_gpu 0`). `igpu`는 iGPU |
| `--num-ctx` | 8192 | 4096은 쓰지 말 것(아래 속도 결과) |
| `--history` / `--layout` | `tools` / `append` | 지난 턴을 도구 호출 형식으로 기록하고, 프롬프트는 뒤에 붙이기만 한다 |
| `--max-turns` / `--trim-to` | 20 / 10 | 지난 턴이 20개를 넘으면 최근 10개만 남긴다 |

## 데모 설정 (`demo/`, 앱에서만 사용)

v1 실험 파일(`cafe_common.py`, `data/tools.json`, `data/menu.json`)은 그대로 두고, 앱에서만 쓰는 설정을 따로 만들었다.

- **`demo/rules.txt`:** v1 시스템 프롬프트의 `[메뉴판]` 바로 앞에 끼워 넣는 규칙이다.
  - 메뉴나 옵션을 묻기만 하면 inform을 부르고, 메뉴·옵션을 글로 나열하지 않는다.
  - 되묻기는 짧은 한 문장으로, 고를 것은 최대 3개까지만 말한다.
- **`demo/inform_tool.json`:** `inform(topic, item?)`. topic은 category_items, sizes, temperatures, options, not_offered, item_detail 중 하나다.
  - 모델은 topic과 item만 고른다.
  - 답 문장은 `demo_config.inform_answer()`가 **`menu.json`만 보고** 만든다(문구는 `replies.json`의 `inform`).
  - 예: "디저트는 치즈케이크, 초콜릿케이크가 있어요.", "마카롱은 없어요. 디저트는 …"
  - 메뉴를 친구 메뉴로 바꾸면 `menu.json`만 바꾸면 된다.
- **글 답 거르기:** 모델이 도구 없이 글로 답했는데, 메뉴판에 없는 메뉴나 옵션 이름이 들어 있으면 읽지 않는다.
  - 판정 기준: `demo/common_cafe_items.json`의 흔한 카페 메뉴·옵션 목록, 그리고 메뉴처럼 보이는 단어(…라떼, …에이드, …케이크 등) 중 메뉴 이름과 유사도가 0.8보다 낮은 것.
  - 걸리면 "메뉴 안내는 '디저트 뭐 있어요?'처럼 물어봐 주세요."라고 말하고, 로그에 `kind = free_text_blocked`로 남긴다.

## 답 문장 (`replies.json`)

짧게 말한다. 문구는 `replies.json`에서 고치면 다음 턴부터 바로 반영된다.

| 상황 | 예 |
|---|---|
| 담기 | 네, 아이스 아메리카노 한 잔이요. (새 손님의 첫 메뉴에만 "더 필요하신 거 있으세요?"를 붙인다) |
| 바꾸기 | 네, 샷 반만 넣을게요. (메뉴가 둘 이상이면 "네, 카페라떼는 샷 반만 넣을게요.") |
| 빼기 | 네, 빼 드렸어요. (둘 이상이면 "네, 콜드브루는 빼 드렸어요.") |
| 확정 | 네, 주문 확인했어요. 금방 준비해 드릴게요. (포장이면 "포장으로 주문 확인했어요") |
| 직원 호출 | 잠시만요, 직원 불러 드릴게요. |
| 메뉴 질문 | inform 답(menu.json) |
| 되묻기 / 글 답 | 모델 문장 그대로. 글 답은 위의 거르기를 거친다. |

번호는 읽지 않는다. 화면의 주문 목록에는 번호를 표시한다.

## 화면

- **누르고 말하기:** 버튼이나 Space를 누르고 있는 동안 녹음하고, 놓은 뒤 0.3초 더 녹음한다. 녹음 중에는 빨간 점과 "듣는 중"이 보인다. 토글 모드(한 번 눌러 시작, 다시 눌러 끝)도 있다.
- **끼어들기:** 로봇이 말하는 도중에 녹음을 시작하면(버튼이나 Space), 재생을 곧바로 멈춘다.
- **마이크:** 녹음할 때만 열고 바로 놓는다(블루투스 이어폰 음질 보호). TTS는 원래 샘플레이트(Supertonic 44.1 kHz, Heami 22.05 kHz) 그대로 보낸다.
- **새 손님:** 서버 세션과 주문, 대화 기록, 확정·직원 호출 표시를 모두 지우고 안내를 띄운다.
- **답 표시:** 로봇 답에는 종류를 붙인다. "메뉴 안내", "도구 없이 말로 답함", "메뉴에 없는 이름이 있어 읽지 않음".

## 회귀 확인 (`demo_regression.py`, 결과 `v2/voice/results/demo_regression.md`)

- **조건:** 같은 모델·옵션, 배포용 배치. 채점은 v1 엄격 채점으로 하되 inform 호출은 빼고 센다.
- **예외:** 순수 메뉴 질문(자동 판정: 카페 U1-3, U4-3, 실전 1문항)은 inform만 불러도 정답으로 친다.
- **실전 시험 기록:** id, 유형, 도구 이름, 이유 코드만 남긴다. 질문 문장이나 모델의 자유 문장은 남기지 않는다.

| 실행 | 카페 120 엄격 | 실전 20 엄격 |
|---|---:|---:|
| 5단계 저장 결과 (시험용 배치) | 112 | 14 |
| v1 설정, iGPU (이번) | 112 | 12 |
| 데모 설정, iGPU (이번) | 112 | 11 |
| 데모 설정, CPU 전용 (이번) | 112 | 12 |

- **카페:** 데모 설정에서 2문항이 서로 반대로 바뀌어 합계는 같다(B1-3 X→O, O2-2 O→X).
- **실전 (같은 날 v1 설정 대비):** 데모 iGPU는 −1(L06 X→O, L16 O→X, L19 O→X), 데모 CPU는 ±0이다.
- **실전 (5단계 저장 결과 대비):** 데모 iGPU가 −3이다. 그러나 같은 날 v1 설정도 −2라, 대부분 배치와 실행 편차 때문으로 본다.
- **inform 사용:** 시험에서는 inform을 거의 부르지 않았다(실전 L03 1번, 원래도 오답). 메뉴 질문 2개(U1-3, U4-3)도 되묻기로 답해 정답이었다.

## 속도 (`run_script.py`, `speed_summary.py`, 결과 `v2/voice/results/app_speed.md`)

8턴 글자 스크립트를 설정마다 3번 돌렸고, 중앙값은 24턴 전체에서 구했다.

| 모드 | num_ctx | llm_s | prompt_s | gen_s |
|---|---:|---:|---:|---:|
| iGPU | 8192 | 5.77 s | 4.62 s | 1.07 s |
| **CPU 전용** | **8192** | **4.93 s** | 3.21 s | 1.55 s |
| iGPU | 4096 | 11.28 s | 9.92 s | 1.05 s |
| CPU 전용 | 4096 | 41.52 s | 39.81 s | 1.40 s |

- **CPU 전용을 기본으로 했다.** 약 15% 빠르고, 회귀 결과도 iGPU와 같거나 낫다. 시험 문항당 평균도 3.7초로 iGPU 5.9초보다 짧았다.
- **num_ctx 4096은 쓰면 안 된다.** 데모 프롬프트가 약 4.1k 토큰이라 Ollama가 2,051토큰으로 잘라 버린다(`truncating input prompt`). 그러면 규칙이 사라져 답이 틀리고, 매 턴 처음부터 다시 계산해 훨씬 느려진다.
- **기록 상한을 20/10으로 올렸다.** 6→3으로 줄일 때 404토큰을 다시 계산하느라 CPU에서 한 턴이 12.8초까지 걸렸다.

## 로그와 시험 도구

- **`logs/turns_YYYYMMDD.jsonl`:** 턴마다 인식 결과, 도구 호출, content, 답, kinds, 걸러진 글 답, 시간, 설정을 남긴다. 음성은 남기지 않고, 로그는 커밋하지 않는다.
- **`selftest.py`:** 글자 5턴, 녹음 2개, Heami 미리 듣기를 거친다.
- **`run_script.py --script s8|s9 --label X [--warmup] [--settings JSON]`:** 정해진 대화 스크립트를 돌리고 캐시 재사용량도 기록한다.

## 알려진 한계

- **64e 한 턴 시간:** CPU에서 약 4.5–5.5초이고, 그중 약 3초가 프롬프트 처리다.
- **수량 중복(모델 약점, 앱에서 고치지 않음):** "아아 두잔"이나 "큰 걸로 두 잔이랑 치즈케이크 하나요"에서 같은 메뉴를 1잔과 2잔으로 따로 담은 적이 있다(iGPU, 11-23과 11-24). 11-24 CPU 자체 시험에서는 두 잔 한 줄로 맞게 담았다.
- **되묻기 길이:** 짧게 하라는 규칙이 있어도 길어질 수 있다. 예: "어떤 커피로 드릴까요? 아메리카노, 에스프레소, 콜드브루 중에서 골라주세요."
- **글 답 거르기:** 목록 기반이다. 목록에도 없고 메뉴처럼 생기지도 않은 이름은 지나갈 수 있다.
- **STT 오류:** 메뉴 밖 단어는 잘못 알아듣기 쉽다.
- **세션:** 메모리에만 있다. `/api/ps` 크기 표시(1.25 GB)는 실제 사용량과 다르다.
