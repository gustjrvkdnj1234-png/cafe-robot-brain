# 음성 주문 데모 (2단계)

노트북 하나에서 인터넷 없이 돌아가는 음성 주문 앱이다. 버튼(또는 Space)을 누르고 있는 동안 녹음하고, 떼면 한 턴이 다음 순서로 처리된다.

1. **STT**: faster-whisper medium int8(CPU, 한국어 고정)이 말을 글로 바꾼다.
2. **두뇌**: `song/gemma4-26b-cafe-64e`(v1 64e 전체 빌드, iGPU)가 도구를 호출한다.
3. **답 만들기**: 고정된 한국어 문장 템플릿으로 답을 만든다.
4. **TTS**: Supertonic 3 int8(기본 여성 sid 0, 4단계)이 답을 읽는다. 화면에서 Windows Heami로 바꿀 수 있다.

## 실행

```
powershell -ExecutionPolicy Bypass -File v2\voice\app\start_demo.ps1          # URL을 출력
powershell -ExecutionPolicy Bypass -File v2\voice\app\start_demo.ps1 -Open    # 브라우저도 엶
```

- **Ollama 시작:** `v2\scripts\start_ollama.ps1`로 서버를 띄운다.
  - 환경 변수는 서버 프로세스에만 적용된다: `OLLAMA_IGPU_ENABLE=1`, `LLAMA_ARG_CACHE_RAM=0`(v1과 같음), `OLLAMA_NOPRUNE=1`.
  - 로그에서 NOPRUNE가 켜졌는지 확인한다(로그: `logs\ollama_serve_voice.log`).
  - Ollama가 이미 떠 있으면 설정을 확인할 수 없어서 멈춘다. 그 서버를 그대로 쓰려면 `-UseRunning`을 붙인다.
- **앱 시작:** 엔진을 불러오는 데 약 10초, 64e 예열에 약 30초가 걸린다. 준비되면 `http://127.0.0.1:8770/`을 출력한다(127.0.0.1에서만 열림).
- **종료:** Ctrl+C를 누르면 앱과, 이 스크립트가 띄운 Ollama 서버를 함께 끈다.
- **Python 환경:** `.venv-voice`(Python 3.13). 1단계 패키지에 fastapi, uvicorn, requests를 더했다.
- **모델:** `v2/voice/models/`에 있어야 한다. 받는 방법은 `v2/voice/download_models.py`.

## 화면

- **누르고 말하기:** 버튼을 누르고 있는 동안, 또는 Space를 누르고 있는 동안 브라우저 MediaRecorder로 녹음한다. 녹음 중에는 음량 막대가 보인다.
  - 처음 누를 때는 마이크 권한 창이 뜨므로 한 번 더 눌러야 한다.
  - 0.35초보다 짧은 녹음은 보내지 않는다.
- **글자로 주문:** 마이크 대신 쓸 수 있다.
- **보여 주는 것:**
  - 인식된 말
  - 로봇 답(자동 재생, 다시 듣기 가능)
  - 모델의 도구 호출 JSON(접어 둠)
  - 주문 내역과 확정 표시(매장/포장)
  - 직원 호출 배너
  - 시간: STT, 64e, TTS, 서버 합계, 브라우저 왕복
- **목소리 설정:** 엔진(Supertonic 3 / Windows Heami), Supertonic 화자(sid 0–9, 성별은 음높이로 추정), 단계(4/8)를 고르고 미리 듣기를 할 수 있다. 마지막 선택은 `config.local.json`에 저장된다(커밋 안 함).
- **새 손님:** 주문 내역과 대화를 비운다.

## 동작 규칙

- **프롬프트:** v1과 똑같은 시스템 프롬프트, 메뉴, 도구(`cafe_common.py`, `data/tools.json`)를 쓴다.
  - 배치는 v1 6c 배포용(`bench_latency.build_messages("deploy")`)으로, 주문 내역이 손님의 마지막 말 바로 앞에 온다.
  - 옵션은 시험과 같다: thinking 끔, temperature 0, seed 42, num_ctx 8192, num_predict 512.
- **주문 내역 반영:** v1 직접 주문 페이지와 같은 `robot_ui.apply_calls`를 쓴다.
  - add_item, modify_item, remove_item은 목록을 바꾼다.
  - confirm_order는 주문을 확정 상태로 만든다.
  - call_staff는 직원 호출 배너를 띄운다.
  - ask_clarification은 목록을 바꾸지 않는다.
- **답 문장:** 도구 호출 순서대로 고정 템플릿을 쓴다(`replies.py`).
  - 담기: "아이스 아메리카노 큰 사이즈 두 잔 담았습니다." 연속으로 담으면 한 문장으로 묶는다.
  - 변경: "1번 아이스 아메리카노를 … 바꿨습니다."
  - 삭제: "…를 뺐습니다."
  - 확정: "(포장) 주문 확인했습니다. 총 세 잔입니다."
  - 직원 호출: "직원을 불러 드릴게요. 잠시만 기다려 주세요."
  - ask_clarification은 모델이 쓴 질문을 그대로 읽는다.
  - 도구 호출이 없으면 "죄송합니다, 다시 한 번 말씀해 주시겠어요?"라고 말한다.
- **대화 기록:** 모델에게 돌려주는 기록은 시험 대화처럼 숫자를 쓴다("2잔 담았습니다."). 소리와 화면에는 "두 잔"처럼 우리말 수사를 쓴다.
- **로그:** 턴마다 `logs/turns_YYYYMMDD.jsonl`에 남긴다(인식 결과, 도구 호출, 답, 시간). 음성은 저장하지 않으며, 로그는 커밋하지 않는다.

## 자체 시험 (`selftest.py`, 결과 `v2/voice/results/app_selftest.md`)

앱을 띄운 상태에서 `.venv-voice\Scripts\python.exe v2\voice\app\selftest.py`로 실행한다. 글자 주문 5턴(한 대화), 녹음 2개(builtin 01·07), Heami 미리 듣기를 거친다.

## 알려진 한계

- **64e 시간이 예상보다 길다.** 이 앱의 64e는 한 턴 중앙값 5.2초(4.7–7.7초)다. 1단계에서 예상에 쓴 2.55초보다 길다.
  - 이 값은 v1 6c 배포용 배치 iGPU 측정(첫 토큰 4.7초, 1건 중앙값 6.7초)과 맞는다.
  - 앞부분 약 3,480토큰은 캐시에서 다시 쓰지만, 남은 약 20토큰을 처리하는 데 iGPU에서 약 3.6초가 든다(로그 172 ms/토큰, 컨텍스트 체크포인트 200 MB 2개 생성).
  - v1 6c에서는 CPU 전용 모드가 더 빨랐다(1건 중앙값 4.1초). 이번에는 지시대로 iGPU를 썼다.
- **v1 시험이 다루지 않은 말에서 수량 실수가 나온다.**
  - "아이스 아메리카노 큰 걸로 두 잔이랑 치즈케이크 하나요"에서는 같은 메뉴를 1잔과 2잔으로 두 번 담았다.
  - STT가 "두 잔요."로 적은 녹음에서는 1잔만 담았다.
  - 같은 뜻의 다른 문장 4개("큰 걸로 두 잔이요" 등)는 모두 맞혔다.
  - v1 카페 시험에는 사이즈와 2잔 이상이 함께 나오는 문항이 없다. 수량 2 이상인 시험 문항 10개는 이 앱의 LLM 경로로도 v1과 같이 10/10이다.
- **STT 오류가 그대로 전달된다.** 메뉴 밖 단어가 틀리기 쉽다. 예를 들어 "캐리어"가 "페리얼"로 인식되어, 직원 호출 대신 되묻기가 나왔다. 1단계 CER은 7.1%였다.
- **블루투스 이어폰:** 마이크를 쓰면 통화 모드로 바뀌어 재생 음질이 떨어질 수 있다. 브라우저가 어느 마이크를 쓸지는 브라우저 설정을 따른다.
- **턴은 한 번에 하나씩 처리한다.** 서버 잠금으로 막아 두었고, 세션은 메모리에만 있어 앱을 다시 켜면 사라진다.
- **글꼴:** 오프라인이라 v1 화면의 웹 글꼴(Jua)은 쓰지 않고 시스템 글꼴(맑은 고딕)을 쓴다.
- **`/api/ps` 크기:** Ollama가 이 모델의 크기를 1.25 GB로 보고한다(v1에서도 같음). 실제 사용량은 러너 약 14.3 GB, GPU 공유 메모리 약 14.4 GB다.
