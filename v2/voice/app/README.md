# 음성 주문 데모 (2단계)

노트북 하나에서 인터넷 없이 돌아가는 음성 주문 앱이다. 버튼(또는 Space)을 누르고 있는 동안 녹음하고, 떼면 한 턴이 다음 순서로 처리된다.

1. **STT**: faster-whisper medium int8(CPU, 한국어 고정)이 말을 글로 바꾼다.
2. **두뇌**: `song/gemma4-26b-cafe-64e`(v1 64e 전체 빌드, iGPU)가 도구를 호출한다.
3. **답 만들기**: `replies.json`의 문장 템플릿으로 답을 만든다.
4. **TTS**: Supertonic 3 int8(기본 여성 sid 0, 4단계)이 답을 읽는다. 화면에서 Windows Heami로 바꿀 수 있다.

## 실행과 종료

```
powershell -ExecutionPolicy Bypass -File v2\voice\app\start_demo.ps1 -Open
powershell -ExecutionPolicy Bypass -File v2\scripts\stop_ollama.ps1        # Ollama만 따로 끌 때
```

- **Ollama 시작:** `v2\scripts\start_ollama.ps1`로 서버를 띄운다.
  - 환경 변수는 서버 프로세스에만 적용된다: `OLLAMA_IGPU_ENABLE=1`, `LLAMA_ARG_CACHE_RAM=0`(v1과 같음), `OLLAMA_NOPRUNE=1`.
  - 로그(`logs\ollama_serve_voice.log`)에서 NOPRUNE가 켜졌는지 확인한다.
  - Ollama가 이미 떠 있으면 멈춘다. 그 서버를 그대로 쓰려면 `-UseRunning`을 붙인다.
- **앱 시작:** 엔진을 불러오는 데 약 10초, 64e 예열에 약 30초가 걸린 뒤 `http://127.0.0.1:8770/`을 출력한다(127.0.0.1에서만 열림).
- **종료:** Ctrl+C나 앱 종료 시 앱 프로세스 트리를 끝내고, 이 스크립트가 띄운 Ollama를 `stop_ollama.ps1`로 끈다.
  - `stop_ollama.ps1`은 프로세스와 11434 포트가 모두 닫혔는지 확인한다. 남아 있으면 경고를 내고 exit 1로 끝난다.
  - 예전 버그: 맨 위의 `$ErrorActionPreference='Stop'` 때문에 taskkill이 stderr에 쓴 "process not found"가 종료 처리를 중간에 끊었고, Ollama가 남았다. 이제 종료 단계마다 따로 실행하고, 실패해도 다음 단계로 넘어간다.
- **기록 방식 바꿔 띄우기:** 예를 들어 `-AppArgs "--history text --layout deploy --max-turns 0"`. 옵션은 아래 "대화 기록과 프롬프트"를 참고한다.

## 화면

- **누르고 말하기:** 버튼이나 Space를 누르고 있는 동안 녹음하고, 놓은 뒤 0.3초 더 녹음한다(마지막 음절 보호).
  - 녹음 중에는 빨간 점과 "듣는 중", 음량 막대가 보인다.
  - 0.35초보다 짧게 누르면 보내지 않는다.
  - **토글 모드**(체크 상자)를 켜면 한 번 눌러 시작하고 다시 눌러 끝낸다. 이 설정은 브라우저에 기억된다.
- **마이크:** 녹음할 때만 열고, 끝나면 모든 트랙을 멈추고 AudioContext를 닫는다. 블루투스 이어폰이 통화 모드에서 음악 모드로 돌아갈 수 있게 하려는 것이다.
  - 그래서 누를 때마다 마이크를 다시 연다. 노란색 "마이크 켜는 중…"이 지나간 뒤 빨간 점이 뜨면 말하면 된다.
- **TTS 샘플레이트:** Supertonic 44.1 kHz, Heami 22.05 kHz를 그대로 WAV로 보낸다. 앱 안에서 리샘플링은 하지 않고, 브라우저와 Windows가 출력 장치에 맞춘다.
- **보여 주는 것:**
  - 인식된 말
  - 로봇 답(자동 재생, 다시 듣기). 도구 없이 말로 답했으면 "도구 없이 말로 답함" 표시가 붙는다.
  - 도구 호출 JSON(접어 둠)
  - 주문 내역(화면에는 번호 표시)과 확정 표시, 직원 호출 배너
  - 시간: STT, 64e, TTS, 서버 합계, 브라우저 왕복. 프롬프트 처리 시간도 보인다.
- **목소리:** 엔진, Supertonic 화자(sid 0–9), 단계(4/8)를 고를 수 있고, 마지막 선택은 `config.local.json`에 저장된다. 기본은 Supertonic 3, sid 0, 4단계다.
- **새 손님:** 서버에서 이전 세션을 지우고 새 세션을 만든다. 주문 내역, 대화 기록, 확정과 직원 호출 표시를 모두 비우고, "새 손님이에요…" 안내를 띄운다.

## 답 문장 (`replies.json`)

해요체 카페 직원 말투다. 문장은 `replies.json`만 고치면 되고, 앱을 다시 켜지 않아도 다음 턴부터 반영된다.

| 상황 | 예 |
|---|---|
| 담기 | 네! 아이스 아메리카노 한 잔 추가했어요. 더 필요하신 거 있으세요? |
| 바꾸기 | 네, 바닐라라떼는 샷을 반만 넣어 드릴게요. 더 필요하신 거 있으세요? |
| 빼기 | 네, 콜드브루는 빼 드렸어요. 더 필요하신 거 있으세요? |
| 확정 | 네! 주문 확인했습니다. 빠르게 준비해 드릴게요! (포장이면 "포장 주문 확인했습니다") |
| 직원 호출 | 잠시만요, 직원 불러 드릴게요. |
| 되묻기 | 모델이 쓴 질문을 그대로 읽는다. |
| 도구 없이 말로 답함 | 모델이 쓴 글(content)을 그대로 보여 주고 읽는다. 로그에는 `kind = free_text`로 남긴다. |
| 도구 호출도 글도 없음 | 죄송해요, 다시 한 번 말씀해 주시겠어요? |

- **번호를 읽지 않는다.** 바꾸거나 뺄 메뉴는 주문 안에서 겹치지 않는 가장 짧은 설명으로 부른다. "바닐라라떼"로 겹치면 "아이스 바닐라라떼", 그래도 겹치면 "큰 사이즈 아이스 …", 마지막으로 "두 번째 …" 순이다.
- **한 턴에 문장이 여러 개면** 두 번째 문장부터 "네! / 네, "를 뗀다.
- **"더 필요하신 거 있으세요?"는** 마지막 문장이 담기, 바꾸기, 빼기일 때만 붙인다.

## 대화 기록과 프롬프트 (`server.py` 옵션)

시스템 프롬프트, 메뉴, 도구는 v1 그대로다. 옵션은 시험과 같다: thinking 끔, temperature 0, seed 42, num_ctx 8192, num_predict 512.

| 옵션 | 기본값 | 다른 값 |
|---|---|---|
| `--history` | `tools`: assistant 메시지의 `tool_calls`와 도구마다 `tool` 결과 메시지(`{"ok": …, "robot_said": …}`). 도구 없이 답한 턴은 assistant content. | `text`: 첫 버전처럼 시험식 평문("… 1잔 담았습니다.") |
| `--layout` | `append`: 고정 앞부분(시스템 + 도구) 뒤에 지난 턴을 붙이기만 한다. 각 턴이 본 주문 내역, 손님 말, assistant와 도구 메시지가 이어지고, 맨 끝에 지금 주문 내역과 새 손님 말이 온다. 앞의 메시지는 고치지 않는다. | `deploy`: v1 6c. 주문 내역 메시지 하나를 매번 마지막 손님 말 앞으로 옮긴다. |
| `--max-turns` / `--trim-to` | 6 / 3: 지난 턴이 6개를 넘으면 최근 3개만 남긴다. 줄일 때만 캐시가 다시 만들어진다. | 0 = 제한 없음 |

### 같은 서버에서 번갈아 잰 결과

스크립트 8턴: 커피 한 잔 주세요 / 아메리카노요 / 아이스로요 / 디저트 뭐 있어요? / 아아 사이즈 뭐 있어요? / 아아 두잔 / 카페라떼 반샷만요 / 주문할게요. 결과 파일은 `v2/voice/results/app_script_*.md`.

| 실행 | 기록 / 배치 / 상한 | 도구 없이 말로 답함 | prompt_s 중앙값 | llm_s 중앙값 | 새로 계산한 토큰 (8턴 합) |
|---|---|---:|---:|---:|---:|
| before_r1 | text / deploy / 없음 | 2/8 | 4.54 s | 5.78 s | 529 |
| after_r1 | tools / append / 6→3 | 2/8 | 4.44 s | 5.86 s | 1,161 |
| before_r2 | text / deploy / 없음 | 2/8 | 4.27 s | 5.34 s | 515 |
| after_r2 | tools / append / 6→3 | 2/8 | 4.68 s | 6.08 s | 1,161 |
| tools_deploy (다른 서버 실행) | tools / deploy / 없음 | 2/8 | 4.01 s | 5.47 s | 1,013 |

- **"말로만 답함"은 바뀌지 않았다.** 어느 설정이든 "디저트 뭐 있어요?"와 "아아 사이즈 뭐 있어요?" 두 턴이다. 이런 정보 질문에 답할 도구가 없어서 생기는 일로 보이며, 기록 형식 때문은 아니다. 이전에는 이 답이 버려지고 "다시 말씀해 주세요"를 말했지만, 이제는 그대로 읽는다.
- **지연도 줄지 않았다.** 새로 계산하는 토큰은 턴마다 14–370개뿐이다. 그런데 14토큰만 계산한 첫 턴도 3.6–5.5초가 걸려, 시간 대부분은 요청마다 드는 iGPU 고정 비용이다.
- **tools 형식은 새로 계산할 토큰이 약 2배다.** 앞 턴의 도구 호출과 결과 메시지가 더 길기 때문이다. 다만 시간 차이는 실행마다 흔들리는 폭(같은 첫 요청이 3.6–5.5초) 안에 있다.
- **17턴 기록에서 늘어 보인 것:** 3.8초 → 8.6초는 같은 크기의 재계산(148–149토큰)이 4.8초와 8.6초로 갈린 것이다. 기록이 길어서라기보다 그때그때의 편차로 보인다.
- **기본값은 요청대로 tools / append / 6→3으로 두었다.** 위 결과로는 지연과 말로만 답하기 모두에서 이점이 확인되지 않았다. 되돌리려면 `-AppArgs "--history text --layout deploy --max-turns 0"`.

## 로그와 자체 시험

- **턴 로그:** `logs/turns_YYYYMMDD.jsonl`에 턴마다 남긴다(인식 결과, 도구 호출, content, 답, kinds, 시간, 다음 요청에 넣은 기록 메시지). 음성은 저장하지 않고, 로그는 커밋하지 않는다.
- **자체 시험:** `selftest.py`는 글자 5턴과 녹음 2개를 거친다. `run_script.py --label X [--settings JSON]`은 위 8턴 스크립트를 돌리고 캐시 재사용량을 기록한다.

## 알려진 한계

- **64e 시간:** 한 턴 중앙값이 약 5–6초이고, 그중 프롬프트 처리가 약 4–4.5초다. 요청마다 드는 iGPU 고정 비용이며 v1 6c 측정과 같은 수준이다. v1 6c에서는 CPU 전용이 더 빨랐다.
- **수량 중복은 모델의 약점이다(앱에서 고치지 않음).** 11-24 로그 8번째 턴의 "아아 두잔"에서 같은 메뉴를 1잔과 2잔으로 따로 담았다. 11-23 자체 시험의 "큰 걸로 두 잔이랑 치즈케이크 하나요"도 같다. 이번 8턴 스크립트에서는 이미 담긴 아이스 아메리카노의 수량을 2로 바꿔, 정상이었다.
- **STT 오류:** 메뉴 밖 단어가 틀리기 쉽다. 예를 들어 "캐리어"가 "페리얼"로 인식되면 직원 호출 대신 되묻기가 나온다.
- **append 배치의 주문 내역:** 지난 턴의 주문 내역 메시지가 기록에 그대로 남는다. 최신 내역은 늘 마지막 손님 말 바로 앞에 있다.
- **세션:** 메모리에만 있고, 턴은 한 번에 하나씩 처리한다.
- **화면:** 오프라인이라 시스템 글꼴을 쓴다.
- **`/api/ps` 크기:** Ollama가 1.25 GB로 보고하지만(v1과 같음), 실제 사용량은 러너 약 14 GB다.
